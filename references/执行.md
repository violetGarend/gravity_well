# 执行之井 — 详细设计

> 本文件是"子系统6：执行之井"的详细逻辑文档。
> 核心定位：阶段性导航地图，**不是**待办清单。
> 哲学：引力井是指南针，不是工头。告诉你"航程八周，刚过三周，前方是M2"——而不是"今天必须完成X"。

---

## 1. 设计原则

### 1.1 非线性原则

执行之井不分配每日/每周任务。它只展示：
- 当前位置（当前阶段）
- 剩余航程（剩余时间窗口）
- 前方里程碑（最近要到达的目标）
- 应该避开哪些浅滩（冻结/暂缓项目）
- 当前的天气状况（偏航哨兵）

用户根据这些信息**自己决定**每天的节奏。

### 1.2 单向依赖原则

执行之井是纯读者——读取但不修改战略层数据：

| 文件 | 用途 |
|------|------|
| `铁律.md` | 对齐度基准 |
| `个人信息.md` | 当前状态、项目进展、精力水平 |
| `运营日志/{最新}.md` | 紧急调整建议、系统压力评估 |
| `季度会议/{最新}.md` | 核心杠杆目标、规则修订、交付日期 |
| `勘探记录.md` | 铁律原始来源 |

### 1.3 渐进式披露原则

- **CLAUDE.md**：声明子系统的存在、触发条件、输出格式、持久化位置
- **references/执行.md**：展开所有算法细节
- **对话输出**：只展示导航图，不展示推导过程（除非用户要求）

## 2. 触发方式

### 事件驱动

| 触发事件 | 行为 |
|---------|------|
| 雷达分析完成 | 自动触发，输出"执行之井已根据雷达分析更新阶段导航" |
| 委员会闭幕 | 自动触发，输出"执行之井已根据委员会决议更新阶段导航" |
| 勘探完成（铁律变更时） | 自动触发 |
| 用户说"执行之井"/"当前阶段"/"进度" | 手动触发 |

### 跳过生成的优化

同一会话中，15分钟内重复触发直接输出缓存。

## 3. 核心算法

### 3.1 当前阶段识别

从最新数据中提取"当前阶段"：

1. **最新委员会决议**中的"核心杠杆目标" → 阶段名
   - 如"AI客服毕设" → 阶段名 = "毕设攻坚期"
2. **个人信息.md**的"当前主线" → 阶段描述
3. **赛后握手记录** → 核心战场确认

### 3.2 时间窗口计算

#### 硬截止提取

从以下位置提取外部不可推迟的截止日期：

| 来源 | 提取方式 | 例子 |
|------|---------|------|
| 委员会决议 | "9月前完成" → 2026-09-01 | Q3会议决议 |
| 个人信息.md | "11月进行学位英语考试" → 2026-11-01 | 当前状态 |
| 铁律2硬约束 | "72h通知验证者" → 当前时间+3天 | 规则执行 |
| 运营日志 | "建议……" 中的隐含时间窗口 | 调整建议 |

#### 总时间窗口

```
总时间窗口（周）= (硬截止日期 - 当前日期) / 7
```

若无硬截止，总时间窗口按目标类型默认：

| 类型 | 默认窗口 |
|------|---------|
| 委员会指定核心目标 | 12 周 |
| 雷达紧急调整建议 | 3 周 |
| 学习类目标 | 8 周 |
| 工具迭代 | 2 周 |

#### 已投入时间

从以下数据推算已投入时间：

```
已投入时间 = 当前日期 - 阶段宣布日期
```

阶段宣布日期从最新委员会会议的日期或个人信息中项目的"开始时间"提取。

#### 剩余时间

```
剩余时间 = 总时间窗口 - 已投入时间
```

若剩余时间 < 0，标记为"已超期"，提示"建议重新评估阶段计划"。

### 3.3 里程碑拆解

按目标类型自动拆解为 4 个里程碑：

| 类型 | M1 | M2 | M3 | M4 |
|------|----|----|----|----|
| 软件/产品开发 | 需求与架构 | 核心功能 | 集成测试 | 交付发布 |
| 学习/考试 | 知识框架 | 重点突破 | 模拟冲刺 | 应试完成 |
| 工具/工具链 | 可用 | 实用 | 优化 | 发布 |
| 修复/纠偏 | 问题定位 | 方案设计 | 执行修复 | 验证闭环 |
| 通用/其他 | 启动 | 推进 | 收尾 | 完成 |

每个里程碑分配的时间占比：M1=20%、M2=40%、M3=25%、M4=15%。

#### 里程碑进度推断

从以下数据推断当前到达哪个里程碑：

| 数据信号 | 推断逻辑 |
|---------|---------|
| 运营日志中提到"根因已发现"、""修复中" | M2进行中或M3 |
| 个人信息.md中"已完成发布"、"已开源" | M4已完成 |
| 最近日志中提到"推进中"但无明确发布 | M1或M2 |
| 刚开完委员会，决议刚生成 | M1 |

### 3.4 当前聚焦方向

从以下数据中提取当前应该推进的方向（注意：**不是**每日任务）：

| 来源 | 提取方式 |
|------|---------|
| 委员会决议 | 核心杠杆目标的自然语言描述 |
| 运营日志"紧急调整建议" | 前 1-2 条具体建议 |
| 铁律2硬约束 | 通知/公示义务 |
| 规则义务 | 如"输出日"、"电池日"（作为提醒，非强制） |

### 3.5 冻结项目清单

从个人信息.md的"当前项目"中提取所有非活跃项目，加上委员会决议中明确冻结的项目。

### 3.6 偏航哨兵

从最新运营日志的"已识别的偏航模式"中提取当前活跃的偏航。如果当前阶段与已知偏航模式重叠，发出警告。

### 3.7 人格参考文件辅助判断（委员复核）

每次生成导航图时，**默认模拟**两个委员角色对草稿进行复核。涉及具体技术方向时，可额外模拟对应角色。

**模拟机制**：通过读取 `references/人格skills/` 下的参考文件来模拟角色（与委员会子系统一致）。模拟前先读取对应角色的人格参考文件，理解其表达DNA、心智模型、决策启发式，用第一人称发言。

#### 默认委员分工

| 角色 | 参考文件 | 复核对象 | 判断角度 |
|------|---------|---------|---------|
| **乔布斯** | `references/人格skills/steve-jobs-perspective.md` | 当前聚焦方向 | "这个阶段该聚焦什么？哪些该砍掉？" |
| **芒格** | `references/人格skills/munger-perspective.md` | 当前风险 | "最弱环节在哪？最可能让阶段失败的是什么？" |

#### 按需委员（涉及技术方向时）

| 阶段类型 | 参考文件 | 判断角度 |
|---------|---------|---------|
| 涉及技术选型/架构 | `references/人格skills/andrej-karpathy-perspective.md` | 技术路线是否合理 |
| 涉及成本/工程极限 | `references/人格skills/elon-musk-perspective.md` | 是否有更高效的路径 |
| 涉及长期风险/AGI相关 | `references/人格skills/ilya-sutskever-perspective.md` | 长远视角审视 |

#### 复核流程

```
生成导航图草稿
    ↓
读取乔布斯参考文件 → 模拟乔布斯复核：传入草稿的聚焦方向 + 阶段信息
   → 输出：该聚焦什么 / 该砍掉什么
    ↓
读取芒格参考文件 → 模拟芒格复核：传入草稿的偏航哨兵 + 里程碑信息 + 乔布斯判断
   → 输出：最弱环节 / 风险提示 / 预防建议
    ↓
（可选）按需委员：读取对应参考文件 → 模拟
    ↓
整合：将委员复核追加到导航图"委员判断"区块
    ↓
输出最终导航图
```

#### 委员复核的输出位置

委员判断**不修改**导航图主体数据（阶段/时间/里程碑），只追加到导航图的**"委员判断"区块**，作为独立参考。

```
## 👥 委员判断
**乔布斯**：[聚焦复核 + 该砍掉的事]
**芒格**：[最弱环节 + 风险提示]
```

#### 快速跳过

用户说"快速生成"/"跳过委员"时，跳过委员复核直接输出导航图主体。

### 3.8 加入待办项分析

用户手动加入一个阶段外的待办项时，系统自动分析并给出推荐归位，由用户确认后写入。

#### 触发方式

用户说"加入待办[内容]"，如"加入待办：帮朋友看看简历"。

#### 分析流程

```
收到待办项
    ↓
维度1：与当前阶段冲突判断
   → 直接支持当前核心目标？/ 无关？/ 会挤占剩余时间？
    ↓
维度2：推荐归位
   → 当前聚焦（支持阶段）？
   → 冻结（可推迟到阶段后）？
   → 待办池（阶段外独立）？
    ↓
维度3：时间影响
   → 预计耗时（按任务类型默认值）
   → 是否影响剩余时间窗口（剩余周数）
    ↓
维度4：优先级建议
   → 高 / 中 / 低
    ↓
对话中输出分析结论（不写入）
    ↓
用户确认归位后 → 追加到执行任务.md 对应区块
```

#### 分析判断规则

| 维度 | 判断依据 | 输出 |
|------|---------|------|
| 阶段冲突 | 待办项与当前核心目标的关联度 | 直接支持 / 无关 / 会挤占 |
| 推荐归位 | 冲突判断 + 是否可推迟 | 当前聚焦 / 冻结 / 待办池 |
| 时间影响 | 预计耗时 vs 剩余时间窗口 | 例如"预计3天，剩余4.5周，可容纳" |
| 优先级建议 | 紧急度 + 重要性 | 高 / 中 / 低 |

#### 关键约束

- 分析结论**只在对话中给出，不直接写入导航图**
- 用户确认归位后，才追加到 `执行任务.md` 对应区块
- 遵循执行之井哲学：系统只分析、建议，最终归位决定权在用户
- 待办项归位不影响阶段主体数据（总窗口/里程碑），只作为附加条目

### 执行看板.html 设计

自包含单文件 HTML，无外部依赖。展示：

1. **头部**：阶段名称 + 时间指标（总窗口/已投入/剩余）
2. **进度条**：剩余时间比例可视化
3. **里程碑区**：四个里程碑的横向进度图（●已完成 / ●进行中 / ○待启动）
4. **聚焦方向**：文本列表
5. **偏航哨兵**：红色警告条
6. **委员判断**：乔布斯 + 芒格的复核意见区块

## 5. 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| 无委员会记录 | 基于个人信息.md+最新运营日志生成，标注"无委员会数据" |
| 无运营日志 | 基于委员会+个人信息生成，标注"无雷达数据" |
| 铁律不存在 | 不生成，提示"请先勘探确立铁律" |
| 硬截止已超期 | 标记为已超期，建议重新评估阶段计划 |
| 多个委员会决议冲突 | 以最新为准 |
